### 功能：待回复问题列表与本机答案草稿

#### 前置条件与准备

1. 在当前验收版本的 `http://127.0.0.1:13511` 打开两个测试会话 A、B，记录会话 ID、原主题和当前草稿。不要重启或修改 `13510` 正式实例。
2. 使用隔离测试请求或 Playwright 路由桩准备以下请求。每条请求必须有稳定的 `id`、`generation`、`threadId`、`turnId`、`itemId`、`receivedAtIso`；刷新时返回相同身份。`GET /codex-api/server-requests/pending` 的响应格式为 `{ "data": [...] }`。
   - 会话 A：一条 `item/tool/requestUserInput` 阻塞问题；两条 `request_user_input_async` 且 `params.isBlocking = false` 的异步问题。
   - 每条问题的 `params.questions` 至少包含一个带 `options` 的选择题和一个无选项的文本题；另外分别准备 `isSecret: true` 与兼容标记 `secret: true` 的秘密文本题。只用虚构测试内容，不输入真实凭据。
   - 会话 B：同一数字请求 ID、不同 `threadId` 的文本题，用于验证跨会话隔离；另外准备字符串请求 ID `"7"` 与数字 ID `7` 的隔离用例。
   - 一条命令审批请求，保留现有审批选项和命令预览。
3. 开启开发者工具 Network 的保留日志；关注 `/codex-api/server-requests/pending`、`/codex-api/server-requests/respond` 和聊天 RPC。页面切换、加载测试使用同一测试源站。
4. 在开发者工具 Application 中记录测试前 `localStorage` 的 `codex-web-local.pending-input-drafts.v1` 值。使用独立测试浏览器配置，避免覆盖真实用户草稿。
5. 准备浅色、深色主题和 `375x812`、`768x1024` 两种视口。需要延迟接口或模拟失败时用 Playwright CJS 路由拦截；不要以全站断网替代单接口失败。

#### 操作与预期结果

1. **阻塞优先与手动切换**：打开会话 A，先观察默认展示的请求，然后依次点击两个异步问题，再返回阻塞问题。
   - 待回复数量正确，阻塞请求默认排在前面；标签区分“需要回复才能继续”与“可稍后回复”。
   - 手动选择异步问题后，内容区和选中状态保持在该问题；后台刷新同一 pending 列表不会强行切回阻塞问题。
   - 列表、文本输入和发送操作可通过键盘访问；切换问题不提交任何答案。
2. **逐题草稿与刷新恢复**：在阻塞问题选择一个非默认选项，输入 `draft-A-blocking`；在两个异步问题分别输入 `draft-A-async-1`、`draft-A-async-2`。每次输入后等待至少 300 毫秒，反复切换，再刷新页面并重新选择各问题。
   - 每题恢复各自的选项和文本，提示已保存在当前浏览器；没有串题、恢复默认值或重复字符。
   - 刷新请求对象即使重新创建，身份字段相同仍恢复原草稿；修改请求的 generation、turn、item、接收时间或 ID 类型后，不套用旧草稿。
3. **跨会话隔离**：在会话 B 同 ID 的题目输入 `draft-B`，返回会话 A，再回到 B；刷新后重复。
   - A 和 B 各自恢复对应草稿；数字 ID 与字符串 ID 不互相复用。没有请求的会话不显示前一个会话的问题内容。
4. **慢 pending 加载**：保存会话 A 草稿后，将 `/codex-api/server-requests/pending` 延迟 3 秒，刷新页面。在返回 pending 数据前检查草稿键，再等待请求成功。
   - 加载期间暂时没有问题面板，不等于问题已提交；存储中的草稿不被清空。请求返回后相同题目的草稿可正常恢复。
5. **秘密答案**：在普通文本题输入 `public-draft-marker`，分别在 `isSecret: true` 与 `secret: true` 秘密题输入 `secret-draft-marker`，等待 300 毫秒，检查输入类型、草稿键和刷新后的表单。
   - 秘密题使用 `type="password"`，输入不会以明文显示。存储原文不包含 `secret-draft-marker`，普通答案仍可保存。
   - 刷新后普通答案恢复，秘密答案为空；草稿提示明确秘密答案不保存。输入秘密答案本身不会产生提交请求。
6. **失败保留与成功清理**：将目标 `/codex-api/server-requests/respond` 第一次响应设为 HTTP 500，点击一次发送；随后恢复成功响应，手动重试。成功后从 pending 响应移除该请求。
   - 失败有可见提示，输入与本地草稿保留；按钮恢复可用，用户可以重试。
   - 成功只清理已提交请求的草稿，待回复数量递减；其他问题和其他会话的草稿仍保留。
   - 发送过程中重复点击只产生一个在途提交；成功后切题或刷新不会再次自动发送。
7. **存储数量与时间边界**：在独立测试配置中依次对 25 个不同身份的问题写入草稿；检查存储数组并返回最早的问题。再将一条测试草稿 `updatedAt` 设为 `Date.now() - 7 * 24 * 60 * 60 * 1000`，刷新并选择该问题。
   - 最多保留最近 24 条；第 25 条写入会淘汰最久未更新草稿，编辑旧草稿会刷新其保留顺序。
   - 到期草稿不恢复；未满 7 天的草稿仍恢复。过期记录可能在下一次写入时才从存储文本清除，不能把这一点误判为恢复了过期答案。
   - 使用多条大文本草稿时，整个存储字符串不超过 `128 * 1024` 个字符；单条序列化草稿超过 `16 * 1024` 个字符时提示保存不可用，已有保存值不被覆盖。
8. **输入性能与请求次数**：清空 Network 记录，在已加载题目里连续键入至少 30 个字符并切换三次题目；等到草稿保存提示出现，再手动发送一次。
   - 逐键输入、草稿保存和本地切题均不触发回复或聊天发送 RPC；仅明确发送产生对应回复请求。常规后台 pending 拉取不能随字符数量成倍增加。
   - 连续输入采用约 250 毫秒防抖保存；没有每键完整写盘的持续高频行为。用性能录制检查输入不卡顿，无不随题目数上限收敛的存储扫描或请求扇出。
9. **审批回归**：在问题列表中切到命令审批请求，检查命令预览，分别用独立请求验证允许、拒绝和跳过。再回到一个仍待回复的问题。
   - 审批操作沿用原有决策 payload，实际命令与选项不被问题草稿覆盖；每个审批只有一个可操作面板。
   - 审批输入不会写入问题草稿；处理审批不会删除其他请求的答案或触发其他问题的自动提交。
10. **明暗主题与窄屏**：在 `375x812`、`768x1024` 视口分别重复问题切换、选择题菜单、长文本输入、失败提示和审批展示；切换浅色、深色主题。最后操作后等待 2–3 秒再截图。
    - 真正的问题面板和选中项可见，列表不造成页面横向溢出；题目较多时仍能访问每题。按钮、草稿提示、菜单、输入框无截断或重叠。
    - 深色主题不存在残留浅色面板，选中/未选中及禁用/可用状态可区分；浅色主题文字对比正常。
    - 每张截图记录实际 URL、视口、主题及断言结果，保存到 `output/playwright/pending-response-inbox-<theme>-<width>x<height>.png`。

#### 回滚与清理

- 撤销 pending/response 延迟和故障路由桩，关闭测试请求；不要给真实未决问题发送虚构测试答案。
- 恢复测试前的主题和视口。删除独立测试浏览器中的 `codex-web-local.pending-input-drafts.v1`，或精确恢复准备阶段记录的原值；不要清空其他 localStorage 项。
- 清理专用测试会话与生成的虚构草稿，保留截图和验证记录。停止测试专用拦截脚本；保持验收服务状态，勿操作正式服务。
