# 第二批原生会话控制

## 原生协议与能力发现

- 前置条件：第二批构建、固定 Codex CLI 0.153.4、独立 CODEX_HOME；业务验收使用 13511，不使用 13510。保留一个旧 CLI 环境用于兼容性检查。
- 操作：请求 `/codex-api/meta/methods` 与 `/codex-api/meta/notifications`，重复并发请求；确认包含当前 CLI 实际提供的 `turn/steer`、设置、Goal、队列及权限方法。
- 预期：同一 CLI 身份只执行一次 Schema 生成；实验方法按实际目录发现；临时 Schema 目录在读取后删除。缺少方法时对应能力不可用，不通过猜版本冒充支持。
- 操作：对隔离线程的活动回合发送 `turn/steer`，携带精确的 `expectedTurnId`、文本、图片及 skill 输入；再以错误或过期回合 ID 重试。
- 预期：正确输入进入原回合；请求不携带模型、权限或其他 turn/start 设置。不额外调用 turn/start 或 resume；错误请求不自动重发或改开新回合。
- 操作：分别更新运行回合和会话后续设置，覆盖 `serviceTier: null` 与字段省略；模拟 `targetUnavailable`。
- 预期：两个设置作用域严格区分；null 与省略不混淆；目标已结束不是“修改成功”。权限不允许作为运行回合设置提交。
- 清理：只清理本轮隔离测试线程；不迁移或覆盖正式历史，不为部署复制备份。

## 协议层性能审计

- 自动测试以 20 个并发目录请求验证只生成一次 Schema；生成结果同时供方法和通知目录复用。
- 能力读取在前端合并并发请求；目录缓存随 CLI 路径、文件大小或修改时间变化失效，失败允许重新读取。
- 权限和原生队列分页最多 20 页、2000 项；重复游标明确报错，不无限请求。
- 队列提交结果不确定时只查询对账，不重发 add，不根据 HTTP 超时擅自恢复旧发送路径。

## 队列归属与持久化

- 前置条件：独立 HOME，准备含逐条模型/规划选项的旧队列，以及一个空闲空队列会话。
- 操作：旧队列非空时尝试启用原生队列；空队列切换成功后，用旧标签页提交旧队列写入，再尝试非空时切回。
- 预期：旧消息不迁移、不丢弃、不降级其设置；冲突返回 409。原生写入与归属切换按线程串行，旧调度器不能领取原生线程。
- 操作：重新加载 WebUI、刷新项目/置顶/标题，再读取原生归属；模拟归属文件损坏。
- 预期：归属保存在独立 `CODEX_HOME/webui-native-queue-owners.json`，不被共享 `.codex-global-state.json` 的其他写入覆盖；损坏时明确失败，不默认为兼容队列。
- 操作：运行中或待审批时尝试原生 queue/start。
- 预期：拒绝另开回合；CLI 已自动领取的消息不重新发送。原生排队消息只存输入，执行设置继承 CLI 会话，不伪造逐条覆盖。
- 性能：每线程 mutation 锁上限 64 个活跃线程，归属最多 4096 个线程；无新增原生轮询/调度器。列表读取最多 8 MiB；通知合并 120 ms，列表只在选中原生队列、操作后或原生通知时刷新。
- 清理：待两种队列为空且会话空闲后切回兼容队列；不要删除含待执行输入的队列或归属文件，不操作 13510。
