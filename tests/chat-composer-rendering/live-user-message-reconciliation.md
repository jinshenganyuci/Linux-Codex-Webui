# 实时用户消息去重与插话顺序

## 前置条件
- 隔离验收服务，支持原生 `turn/steer` 的 CLI，以及一个自建测试聊天。
- 使用手机和桌面视口、明暗主题。保留发送请求、实时通知和历史响应记录。

## 操作
1. 完成若干轮聊天，再让模型先输出较长进度说明、执行一个等待命令。
2. 执行中选择“引导”，追加带两张图片的唯一标记消息。
3. 在点击后、确认后、执行中刷新后和完成后，检查用户气泡位置和数量。
4. 连续发送两次相同文字“继续”，检查实际发送次数与用户气泡一一对应。
5. 注入重复用户条目通知，分别让历史返回 `item-N` 和规范 ID；也测试旧响应晚于新通知返回。
6. 超时或断网时核对后台，确认不会自动重新发送未确认的插话。

## 预期
- 插话立即出现在已显示的实时回复之后；确认后就地更新，刷新前后均不重、不丢、不倒序。
- 一次实际发送对应一条气泡；两次相同内容仍保留两条。
- 去重限定在同线程、同回合及对应条目，附件不同不能误合并。
- 同步合并突发通知，不逐 token 全量刷新历史；读取旧消息不丢弃尚未确认的发送。

## 清理
- 结束自建测试回合，关闭测试浏览器；不操作正式聊天。
