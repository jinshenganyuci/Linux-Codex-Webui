### Feature: 新聊天使用实际发送模型自动生成标题

#### Prerequisites

- 应用从当前仓库构建并运行，Codex CLI 可用且已完成可用的模型配置。
- 新聊天模型选择器中至少有一个可发送的模型，例如 `gpt-5.6-terra`。
- 使用独立的测试聊天，避免覆盖需要保留的标题。

#### Steps

1. 在新聊天中选择一个模型，例如 `gpt-5.6-terra`，输入：`分析 https://github.com/jinshenganyuci/Linux-Codex-Webui 这个项目`，然后发送。
2. 立即确认用户消息、运行状态和主聊天回复照常出现；发送动作不能等待标题生成完成。
3. 等待标题生成请求完成（最长约 25 秒），检查侧栏和聊天标题。
4. 确认标题是可读的任务名，例如 `分析 Linux-Codex-Webui 项目`，而不是以 `https://`、本地路径或命令开头。
5. 刷新页面，确认自动标题仍存在。
6. 新建另一条测试聊天并发送消息后立即手动重命名；等待后台标题请求结束，确认手动名称没有被覆盖。
7. 在浏览器网络面板检查 `generate-thread-title` 请求参数：`model` 应等于新线程实际创建后返回并显示的模型；若发送时发生模型回退，标题请求应使用回退后的实际模型。
8. 检查聊天列表，确认标题生成没有新增可见聊天、没有向当前聊天插入额外消息，也没有改变主任务的模型选择。

#### Expected Results

- 每个新聊天最多发起一次后台标题生成；标题请求独立于主聊天发送流程。
- 标题生成通过 `codex exec --ephemeral` 运行，不写入 Codex 会话历史、不产生隐藏的聊天线程。
- 同一时间最多运行一个标题生成任务；排队已满、超时或模型调用失败时，聊天仍可正常使用并保留现有临时标题。
- 刷新后自动标题可恢复；手动重命名优先，后台结果不会覆盖人工名称。

#### Rollback/Cleanup

- 删除测试聊天即可；标题生成不会留下 Codex 会话文件。
- 回退本功能提交并重新构建前端和 CLI 即可恢复原来的首行临时标题行为，无需迁移聊天数据。
