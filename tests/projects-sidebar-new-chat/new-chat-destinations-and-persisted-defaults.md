# 新聊天目的地与持久化默认模型

## Feature/Change Name

顶部与 Chats 新建入口默认归入 Chats，项目新建入口保留项目目录，新聊天模型和推理强度按 provider 服务端持久化。

## Prerequisites/Setup

1. 在当前工作树构建前后端，并使用 `127.0.0.1:13511` 启动验收实例。
2. 侧边栏至少有一个项目和一条项目聊天，且当前 provider 至少提供两个可选模型。
3. 准备两个独立浏览器会话（不共享 `localStorage`），但访问同一 WebUI/CODEX_HOME。

## Steps

1. 在浅色主题打开一条项目聊天，点击侧边栏顶部铅笔。
2. 确认进入新聊天页且未选择原项目目录；发送唯一标记 `global-chats-<timestamp>`。
3. 展开 Chats，点击 Chats 标题右侧铅笔，发送 `section-chats-<timestamp>`。
4. 点击某个项目标题右侧铅笔，确认文件夹选择器显示该项目的精确目录，发送 `project-chat-<timestamp>`。
5. 打开设置，在“新聊天默认模型”中选择一个非 Codex 配置默认的模型，再选择该模型支持的“新聊天默认推理强度”。
6. 在网络面板确认每次选择只产生一个 `PATCH /codex-api/preferences/new-chat-defaults`，不额外请求模型目录。
7. 再次点击顶部铅笔，确认 composer 显示新默认模型和推理强度；然后在本次草稿中手动切换到另一组值，触发普通刷新并确认手动值未被覆盖。
8. 打开一条已保存不同模型/推理强度的旧聊天，确认它仍显示自己的线程偏好，不被新聊天默认值覆盖。
9. 在第二个独立浏览器会话打开同一实例，确认设置面板恢复相同的新聊天默认值；新建聊天后 composer 也使用这组值。
10. 将模型切换到不支持当前默认推理强度的模型，确认推理强度自动回退到该模型的默认值或首个支持值。
11. 在深色主题重复打开设置和三个新建入口，检查面板、下拉菜单、文字、错误行和选中态的可读性。

## Expected Results

- 顶部铅笔和 Chats 铅笔创建的对话都出现在 Chats，不继承当前或上一次项目目录。
- 项目铅笔创建的对话出现在所点项目下，首次发送使用该项目目录。
- 新聊天默认值按 provider 保存在服务端，同一 CODEX_HOME 跨浏览器恢复；选择“跟随 Codex 配置”会删除对应显式字段。
- 优先级为当前草稿手动选择、provider 新聊天默认、Codex 配置、可用模型回退；已有聊天始终使用自己的线程偏好。
- 设置修改不重新加载模型目录，不触发 `thread/list`、历史读取或无界请求。
- 浅色和深色主题下均无浅色漏出或不可读状态。

## Rollback/Cleanup

- 将两个设置恢复为“跟随 Codex 配置”。
- 归档或删除三条带唯一标记的测试聊天。
- 如需完全重置测试实例，仅删除该实例 CODEX_HOME 中的 `linux-codex-webui-new-chat-defaults.json`，不要删除正式实例文件。
