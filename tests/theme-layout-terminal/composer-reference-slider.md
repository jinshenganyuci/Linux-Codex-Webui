# 输入区参考布局与思考强度滑杆

## 准备与范围

以用户提供的桌面和手机截图为参考。日常验收地址为独立 `http://127.0.0.1:13511`，不得在未另获正式升级指令时改动 13510。沿用 iOS 页面主题，底部改用中性边框、轻阴影、紧凑控件。

准备一个已完成的验收聊天并记录其模型/推理偏好。视口为 1440×900、768×1024、375×812、376×640，分别验证明暗主题。后两组使用触摸输入，较矮窗口开启减少动态效果。包含启动偏好读取期间立即选择新模型的竞态回归。

## 操作与预期

1. 点击输入框并输入多行草稿：边框没有蓝色光圈；发送按钮、附件、模型菜单和正文仍可用。桌面左侧为「＋、权限」，右侧为「上下文圆环、模型与强度、发送」；手机保留语音入口，权限和技能从「＋」访问。会话控制、目标和扩展入口仍在「＋」内。
2. 点击模型/强度：桌面出现锚定于触发按钮的紧凑面板，手机出现大尺寸滑杆。拖动时滑块连续跟手，标题显示当前档位，松手后吸附并保存；一次拖动最多写入一次模型偏好，取消触摸不保存。
3. 将支持 Ultra 的模型滑至最右端：显示 Ultra 和紫色静态渐变。滑杆档位根据实际模型能力生成，不为不支持的模型添加档位；未知能力沿用应用原有回退选项并在配置说明中提示。无可调强度时不显示可操作滑杆。
4. 聚焦滑杆，用左右箭头、Home、End 调整；按重置按钮恢复当前模型目录报告的默认强度。未提供默认强度时重置按钮不可用。按 Esc 或点空白处关闭；关闭后重新打开及刷新，已保存的模型与强度一致。调档沿用既有后续消息设置语义，不承诺改变运行中的步骤。
5. 点击面板标题进入模型配置：桌面为同位置菜单，手机为底部配置面板。切换模型后，返回滑杆核对该模型的档位；打开速度菜单，标准/快速及禁用状态与实际能力一致。「完成」或外部点击可关闭。缩小视口后列表可滚动，底部操作可达。
6. 查看上下文小圆环：仅在有真实用量时出现，悬停/点击显示已用比例、上下文 token 数和窗口上限；保留详情，不在圆环中心塞数字。可用浏览器本地用量夹具检查视觉，但必须明确标注，不能冒充真实推理输出。
7. 打开权限菜单：原生模式只列 CLI 允许的 profile，已知 ID 显示中文名称；自定义 profile 保留原有标识，权限作用域和说明不变。无配置或加载失败有明确状态。权限异步加载后菜单重新定位，不能被底边裁切；不因修改标签而放宽权限。
8. 连续打开权限和会话控制：权限列表读取合并且在当前线程复用，切换线程后不接受旧线程迟到结果；实际权限变更继续由原控制器应用到当前会话后续回合。原生面板内搜索权限时，Esc 依次清空搜索、关闭子菜单、关闭面板，不一次穿透两层。
9. 打开「＋ → 技能」并点击搜索列表：父菜单不能提前卸载子菜单。打开会话控制并关闭，输入框和消息边界保持对齐，焦点回到可见入口。快速反复打开关闭、切换聊天后没有残留监听器或浮层。

## 自动验收与清理

```bash
pnpm run build:frontend
pnpm exec vitest run src/composables/desktop/nativeThreadController.test.ts src/components/content/sheetMotion.test.ts src/runtimeItems.test.ts
node scripts/verify-composer-reference.cjs
LIVE_PREVIEW=1 node scripts/verify-composer-reference.cjs
```

脚本直接使用 Playwright，因为需要设置主题/用量 localStorage、构建阶段拦截资源、通过 CDP 验证真实触摸取消事件。构建阶段阻止 Service Worker；发布阶段保留 Service Worker 并检查刷新。脚本会临时改变指定隔离验收聊天的模型偏好，finally 恢复原值，不发送消息、不创建项目、不修改权限或速度。测试结果保存在 `output/playwright/composer-reference/`。

截图报告地址均为 `http://127.0.0.1:13511/#/thread/<验收 ID>`，具体 ID、视口、请求及断言结果见 `live-result.json`。上下文 24k/258k 为已标注的浏览器本地视觉夹具，模型偏好保存/回读使用真实接口。

## 启动期间模型选择保护

真实浏览器检查发现，初始偏好读取可能晚于手动模型选择返回，把新选择恢复成旧模型。读取前记录偏好对象快照，合并响应时保留请求期间被替换的条目；模型目录加载结束后同样读取当前选择，并拒绝切换聊天后的迟到结果；既有串行写入和失败反馈不变。两类延迟读取单测确认模型与强度不会被旧响应覆盖，浏览器还断言滑至 Ultra 时实际 PUT 的 model 必须为刚选中的 Astra。此前只检查 effort 字段不足以证明模型也正确，最终以同时检查两字段的复验为准。

## 性能审计与部署

- 前端类型检查和构建通过，4 个相关测试文件、175 项单测通过；8 组真实服务检查通过，另有原会话控制/输入区明暗 6 组回归通过。拖动过程中设置写入为 0，松手后为 1；取消为 0，刷新后值保留。
- 主入口 JS 从 709105 增至 713466 字节，gzip 从 219594 增至 222052；主 CSS 从 527002 增至 534686 字节，gzip 从 58091 增至 60148。保留原有大 chunk 构建提示，没有新增依赖。
- 滑杆每次拖动开始读取一次尺寸，移动中不读取布局或发请求，松手后的有界弹簧停止后不再占用帧。菜单仅打开时挂载布局监听器和 ResizeObserver；通用菜单观察自身内容尺寸，解决异步列表被屏幕裁切。
- 权限列表只在打开相关菜单时读取，复用已有分页上限、控制器时序保护及并发合并；当前线程复用结果，切换线程或运行时重载失效。没有新增启动请求、定时轮询、全量历史扫描或逐 token 工作。初始偏好合并仅遍历已有的本地偏好条目，不创建额外 GET、并行扇出或更大的服务端响应，沿用原缓存加载边界。
- 13511 仅原子更新静态资源，不创建备份、不重启服务；13510 文件哈希与两服务 PID 保持不变。后端继续使用原构建，前端版本单独写入部署回执。回退应从指定提交构建前端并同样先发布资源、后替换入口。
- Chromium 触摸视口与减少动态效果已测；真实手机键盘、Safari/Firefox 和低端 GPU 未实测，不作等同承诺。
